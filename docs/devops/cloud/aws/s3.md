# Amazon S3

Simple Storage Service – fully managed **object storage**. Buckets store, organize and retrieve any amount of data:
files,
images, videos, backups, application data.

## Key features

1. **Object storage** – each object = data + metadata (key-value pairs) + a unique key.
2. **Flat structure** – no real folders; key prefixes like `folder1/file.txt` simulate a hierarchy.
3. **Accessible via URLs** – `https://<bucket-name>.s3.amazonaws.com/<object-key>`.
4. **Durability and availability** – designed for 99.999999999 % (11 nines) durability.
5. **Virtually unlimited scale.**
6. **Access control** – secure by default. Use **bucket policies** and **IAM roles/policies**; keep **Block Public
   Access** on.
   ACLs are legacy – new buckets have them disabled by default (since April 2023) – avoid them.
7. **Storage classes** – by cost/access pattern: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier
   Instant /
   Flexible Retrieval / Deep Archive, Express One Zone, and Outposts (S3 APIs on-premises).
8. **Event notifications** – trigger Lambda/SQS/SNS on upload/delete.

## Use cases

Backup and recovery · archiving (Glacier classes) · static website hosting · big-data analytics (Athena, Redshift) ·
content
distribution with CloudFront · application data (uploads, logs).

## Key concepts

- **Bucket** – top-level container; the name is **globally unique** across AWS accounts.
- **Object** – key + data + optional metadata (content type, creation date…).
- **Key** – e.g. bucket `my-bucket`, key `photos/2023/photo.jpg`.
- **Permissions** – bucket policies, IAM roles/policies (ACLs only for rare per-object cases).

## Setting up

1. Create bucket (console → S3 → Create bucket; name, region, settings).
2. Upload objects (console, CLI, SDKs, API).
3. Configure permissions (private by default).
4. Enable features: versioning, encryption, logging, event notifications.

## Python (Boto3)

```python
import boto3

s3 = boto3.client('s3')

s3.upload_file("local_file.txt", "my-bucket", "folder1/remote_file.txt")
print("File uploaded successfully!")

s3.download_file("my-bucket", "folder1/remote_file.txt", "downloaded_file.txt")
print("File downloaded successfully!")
```

## Best practices

1. Enable **versioning**.
2. **Encrypt** data (SSE-S3 / SSE-KMS, or client-side).
3. **Lifecycle policies** – transition to cheaper classes or delete after a time.
4. **Secure access** – IAM roles/bucket policies; avoid public buckets unless necessary.
5. **Logging** – bucket logging / CloudTrail.

## Limitations

- Bucket names must be globally unique.
- Max object size 5 TB; a single PUT is limited to 5 GB – larger objects need **multipart upload** (recommended from ~
  100 MB).
- Retrieval from archive classes (Glacier) is slower.

## Pricing factors

Storage (per GB-month) · requests (PUT, GET, DELETE, LIST) · data transfer out.
See [S3 pricing](https://aws.amazon.com/s3/pricing/).

## Static website hosting

S3 can host static sites (HTML/CSS/JS). For custom domains, HTTPS and caching the usual solution is **S3 + CloudFront**
(CDN
with custom domains, TLS and caching). See [CDN](../../../architecture/caching-and-cdn.md).
